# 악보 추출 앱 (가칭) — 백로그

기획: [`docs/악보추출앱_기획.md`](docs/악보추출앱_기획.md) (2026-10-16 받음, 이하 "기획")

**위에서부터 하나씩** 진행하고, 끝나면 상태를 고치고 커밋 해시를 적는다.
상태: `대기` · `진행중` · `완료` · `보류` · `확인필요`

이 앱은 앞의 앱들과 성격이 다르다. **품질을 좌우하는 것은 화면이 아니라 AI 파이프라인**이다.
채보 품질이 쓸 만한지 모르는 상태에서 화면·결제부터 만들면 전부 버릴 수 있다. 그래서
① PC 에서 파이프라인을 먼저 만들고 **숫자로 품질을 잰 뒤** ② 앱 ③ 서버·결제 순으로 간다.

---

## 이 환경의 제약 — 기획에 없던 것

| 제약 | 영향 | 대응 |
|---|---|---|
| **GPU 가 없다** (WSL2, CPU 12코어, RAM 15GB) | 음원 분리(Demucs)·채보 모델을 CPU 로 돌려야 한다 — 곡당 수 분 | 개발·평가에는 충분하다. 처리 시간을 R 항목마다 재서 서버 사양(C-2)의 근거로 쓴다 |
| **저작권 있는 곡으로 시험할 수 없다** | 실제 유튜브 곡을 받아 품질을 재면 그 자체가 기획 4장의 위험을 저지른다 | 정답 MIDI 가 붙은 **공개 연구용 데이터셋**으로 잰다 — 피아노는 MAESTRO(CC BY-NC-SA 4.0, 실제 연주 녹음 + 정렬된 MIDI), 밴드 음악은 Slakh2100(CC BY 4.0, 악기별 스템 + MIDI). **데이터는 커밋하지 않는다** |
| 에뮬레이터 불가, 실기기는 태블릿 / LG V35 | 앱 화면은 골든 이미지와 APK 사이드로드로 확인 | 톡톡런과 같은 방식 |

## 기획 검토 — 그대로 하면 안 되는 것

| 기획 | 문제 | 대신 |
|---|---|---|
| 1장 "YouTube URL 에서 오디오 추출" | **YouTube 약관이 다운로드를 금지**하고, **Play 스토어 정책도 YouTube 콘텐츠를 내려받는 앱을 거절**한다. 서버에서 받으려 해도 YouTube 는 데이터센터 IP 를 봇으로 막는다. 즉 핵심 경로가 법·스토어·기술 세 곳에서 막힌다 | **C-1** 참고. 기본안: 사용자의 오디오 파일(파일 선택 + 다른 앱에서 "공유하기")을 정식 경로로 삼는다 |
| 1장 Spleeter | 2019년 TF1 모델, 사실상 유지보수가 끝났다 | **Demucs v4 (htdemucs)** 로 시작 |
| 1장 Omnizart | 오래된 TensorFlow 에 묶여 설치부터 어렵다 | 피아노: **ByteDance piano_transcription** (PyTorch, 페달까지), 그 밖의 악기: **Spotify Basic Pitch** (가볍고 ONNX/TFLite 모델이 있어 **기기 안 실행** 후보). R-3 에서 둘을 같은 데이터로 비교 |
| 2장 피아노 롤 + 음표 수정 | 맞다. 다만 AI 출력(초 단위 음표)을 **악보(마디·박·음가)로 바꾸는 양자화**가 기획에 빠져 있다 — 가독성은 모델보다 여기서 갈린다 | R-5 로 따로 둔다 |
| 추가 "릴리즈 모드 3 credit, 1 credit = 1 추출" | credit 을 **기기에만 저장하면 앱 데이터 삭제로 무한 충전**된다. 구독·구매도 영수증을 서버가 확인해야 한다 | credit 원장은 **서버**에 둔다 (S 절). 테스트/릴리즈 구분은 빌드 flavor 로 |

### R-3 결과 — MAESTRO 실제 피아노 녹음 8곡 (test 분할, CPU 12코어)

| 방식 | onset F1 | onset+offset F1 | 처리 시간 / 곡 길이 | 최대 메모리 |
|---|---|---|---|---|
| 단선율 기준선 (pYIN) | 0.198 | 0.084 | 0.03 | 428MB |
| Basic Pitch (ONNX) | 0.740 | 0.245 | **0.01** | 539MB |
| **ByteDance 피아노** | **0.976** | **0.860** | 0.95 | 1.1GB |

- **96kbps mp3 로 압축해도 거의 그대로다** (앞 60초: 피아노 0.977 → 0.975, Basic Pitch 0.754 → 0.752). 기획 1장의 "압축으로 배음 손실" 걱정은 채보 점수로는 크지 않다 — 정규화는 레벨·채널을 맞추는 용도로 충분하다.
- **ByteDance 점수는 실제보다 높을 수 있다** — MAESTRO 로 학습했고 평가 곡도 같은 피아노(Disklavier)·같은 녹음 환경이다. 대중음악 피아노 녹음에서는 낮아질 것이다. 저작권 없는 다른 피아노 녹음으로 확인할 거리를 남긴다.
- **결론(잠정):** 피아노 악보는 ByteDance. CPU 로 곡 길이만큼 걸리므로 폰 안 실행은 어렵다(서버 또는 PC). Basic Pitch 는 빠르고 작아 **기기 안 실행 후보** — 단선율·기타·악기 무관용으로 R-4 에서 다시 본다.
