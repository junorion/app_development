# Play 스토어 출시 절차 (사용자가 직접 하는 부분)

앱과 자료는 다 준비되어 있다. 여기서부터는 계정과 신원이 걸려 있어 대신 할 수 없다.
**PC 웹브라우저**에서 https://play.google.com/console 로 진행한다.

## 전체 일정 감각

```
계정 등록 (1~3일, 신원 확인 대기)
   ↓
앱 만들기 + 스토어 등록정보 입력 (1시간)
   ↓
비공개 테스트 트랙에 AAB 업로드 + 테스터 12명 초대
   ↓
※ 12명이 14일 연속 참여   ← 가장 긴 구간. 여기를 통과해야 다음이 열린다
   ↓
프로덕션 액세스 신청 → 검토 (며칠)
   ↓
프로덕션 출시 → 심사 (보통 1~7일)
```

---

## 1단계. 개발자 계정 만들기 (PC 브라우저)

1. https://play.google.com/console 접속 → **시작하기**
2. 계정 유형에서 **개인** 선택 (사업자등록증이 있으면 **조직**이 유리하다 — 아래 참고)
3. 등록비 **미화 $25** 결제 (일회성)
4. 신원 확인 — 신분증 사진과 주소 정보를 요구한다. 승인까지 보통 1~3일

> **조직 계정이면 12명 테스터 요건이 면제된다.** 다만 사업자등록증과 D-U-N-S 번호가
> 필요하고 D-U-N-S 발급에 1~2주가 걸린다. 사업자가 이미 있다면 조직이 훨씬 빠르다.

## 2단계. 앱 만들기

**Play Console → 모든 앱 → 앱 만들기**

| 입력란 | 값 |
|---|---|
| 앱 이름 | `브레인 스도쿠 도쿠도쿠` |
| 기본 언어 | 한국어 – ko-KR |
| 앱 또는 게임 | **게임** |
| 무료 또는 유료 | **무료** |

선언 두 개(개발자 프로그램 정책, 미국 수출법)에 체크하고 **앱 만들기**.

## 3단계. 앱 설정 (왼쪽 메뉴 → 앱 설정 → 대시보드의 목록을 위에서부터)

`LISTING.md` 의 값을 그대로 넣으면 된다.

1. **앱 액세스 권한** → 모든 기능을 제한 없이 사용 가능
2. **광고** → 아니요, 광고가 없습니다
3. **콘텐츠 등급** → 설문 시작 → 이메일 입력 → 카테고리 **게임** →
   `LISTING.md` 의 표대로 전부 **아니요** → 제출
4. **타겟층 및 콘텐츠** → 연령대 **13-15, 16-17, 18세 이상** 선택 (13세 미만은 고르지 않는다)
5. **뉴스 앱** → 아니요
6. **데이터 보안** → 데이터 수집/공유 **아니요** → 제출
7. **정부 앱** → 아니요
8. **금융 기능** → 아니요
9. **건강** → 아니요

## 4단계. 스토어 등록정보 (왼쪽 메뉴 → 성장 → 기본 스토어 등록정보)

`LISTING.md` 의 짧은 설명 / 자세한 설명을 붙여 넣고, 이 디렉토리의 이미지를 올린다.

- 앱 아이콘 → `store/icon-512.png`
- 그래픽 이미지 → `store/feature-graphic.png` (영어 등록정보에는 `feature-graphic-en.png`)
- 휴대전화 스크린샷 → `store/screenshot-1.png` ~ `screenshot-7.png` (영어는 `screenshot-en-*.png`)
- 개인정보처리방침 URL → `https://junorion.github.io/app_development/sudoku/privacy.html`

영어 등록정보도 함께 넣는다: **기본 스토어 등록정보 → 언어 추가 → English (United
States)** → `LISTING.md` 의 영어 문안과 `screenshot-en-*.png`, `feature-graphic-en.png`.

## 5단계. 비공개 테스트에 올리기

> **트랙을 잘못 고르면 14일이 세지 않는다.** "내부 테스트" 는 올리기 쉬워 보이지만
> 12명×14일 요건에 **카운트되지 않는다**. 반드시 **비공개 테스트**에 올린다.

**출시 → 테스트 → 비공개 테스트 → 새 버전 만들기**

1. **Play 앱 서명** 사용 여부를 물으면 **사용**을 선택한다 (권장 · 사실상 필수).
   우리가 만든 키는 이때부터 "업로드 키"가 된다.
2. `sudoku/android/app/build/outputs/bundle/release/app-release.aab` 를 업로드한다.
   지금 만들어 둔 것은 **versionCode 19 / versionName 2.8** 이다.
3. 출시명은 `2.8 (19)` 로 두고, 출시 노트를 적는다:
   ```
   <ko-KR>
   첫 공개입니다. 광고도 인터넷 연결도 없는 스도쿠입니다.
   </ko-KR>
   <en-US>
   First release. A sudoku with no ads and no internet.
   </en-US>
   ```
4. **테스터** 탭 → **Google 그룹으로** 목록 만들기 (이메일을 하나씩 넣는 것보다
   관리가 쉽다 — `TESTERS.md` 참고)
5. 저장 후 **검토 → 비공개 테스트로 출시**.
6. 생성된 **참여 링크(opt-in URL)** 를 테스터들에게 보낸다.

### 테스터 12명 요건

사람을 모으고 14일을 지켜내는 실무는 **[TESTERS.md](TESTERS.md)** 에 따로 적었다
(모집 경로, Google 그룹 관리, 테스터에게 보낼 안내문, 자주 겪는 문제). 요점만:

- **12명이 동시에** 옵트인 상태로 **14일 연속**. 누적 12명이 아니다
- 한 명이 빠지면 **그날부터 다시 14일**. 그러니 **15~20명**을 모은다
- 서로 다른 **실제 Google 계정**. 개발자 본인 계정은 세지 않는다

## 6단계. 14일 뒤 — 프로덕션 액세스 신청

**Play Console 대시보드**에 "프로덕션 액세스 신청" 항목이 열린다. 신청서에는
테스트에서 무엇을 배웠는지, 피드백을 어떻게 반영했는지를 적는다. 형식적인 문답이지만
성의 있게 쓰는 편이 통과가 빠르다.

## 7단계. 프로덕션 출시

승인되면 **출시 → 프로덕션 → 새 버전 만들기** 에서 같은 AAB(또는 새 버전)를 올리고
국가/지역을 선택한 뒤 출시한다. 심사는 보통 며칠 걸린다.

순서를 택했다 (`../DESIGN-2.md`).
