# 프로젝트: 스도쿠 (Play 스토어 정식 출시 목표)

## 목표
Play 스토어에 정식 등록할 수 있는 수준의 스도쿠 앱을 만든다. N-Queens 는 "동작하는
데모"가 기준이었지만 이번에는 **낯선 사용자가 설치해서 계속 쓰는 앱**이 기준이다.
따라서 기능 누락·어색한 조작·저장 유실은 모두 결함으로 본다.

웹앱(GitHub Pages)과 안드로이드 APK 두 형태로 낸다. 웹 소스는 `sudoku/index.html`
하나이고, 안드로이드는 그것을 감싸기만 한다 (`webview-apk-wrapping` 원칙).

## 핵심 규칙 (게임 로직)
- 9×9 격자를 1~9 로 채운다. 각 행, 각 열, 각 3×3 박스에 1~9 가 한 번씩만 들어간다.
- 문제로 주어진 숫자(given)는 지우거나 바꿀 수 없다.
- 모든 칸이 채워지고 규칙 위반이 없으면 완료다.

## 기능 요구사항

### 퍼즐
1. **퍼즐 자동 생성**: 매 게임 새로 만든다. 내장 퍼즐 목록을 쓰지 않는다.
2. **유일해 보장**: 생성한 퍼즐의 해가 정확히 하나임을 검증한다. 해가 둘 이상이면 버린다.
3. **난이도 4단계**: 쉬움 / 보통 / 어려움 / 전문가. 주어진 숫자 개수와 필요한 풀이
   기법으로 구분한다. 난이도를 고르면 새 게임이 시작된다.

### 입력
4. **칸 선택 → 숫자 입력**: 칸을 누르고 숫자 패드를 누른다. 데스크톱에서는 방향키
   이동과 1~9 키, Delete/Backspace 지우기를 지원한다.
5. **메모(연필) 모드**: 토글하면 한 칸에 여러 후보 숫자를 작게 적을 수 있다. 그 칸에
   확정 숫자를 넣으면 메모는 지워진다. 확정 숫자를 넣으면 같은 행·열·박스의 해당
   후보 메모를 자동으로 지운다.
6. **지우개**: 선택한 칸의 입력(확정 숫자 또는 메모)을 지운다. given 은 지워지지 않는다.
7. **되돌리기 / 다시하기**: 입력·지우기·메모 변경을 되돌릴 수 있다. 횟수 제한 없음.

### 도움
8. **오류 표시**: 규칙을 위반한 숫자를 즉시 표시한다. 어떤 칸과 충돌했는지도 함께 보인다.
9. **힌트**: 선택한 칸의 정답을 채워 준다. 칸을 고르지 않았으면 채울 수 있는 칸을 하나
   골라 채운다. 사용 횟수를 기록해 결과에 표시한다.
10. **강조**: 선택한 칸의 행·열·박스, 그리고 같은 숫자가 들어간 칸을 강조한다.
11. **숫자별 잔여 개수**: 숫자 패드에 각 숫자가 몇 개 남았는지 표시하고, 9개를 다 쓴
    숫자는 비활성으로 보인다.

### 진행 상태
12. **타이머 / 일시정지**: 경과 시간을 표시한다. 일시정지하면 보드를 가린다.
13. **이어하기**: 앱을 껐다 켜도 진행 중이던 게임(보드·메모·타이머·되돌리기 기록)이
    그대로 복원된다. 저장은 localStorage 를 쓰되 접근이 막혀도 앱이 죽지 않아야 한다.
14. **기록 통계**: 난이도별 완료 횟수, 최고 기록, 평균 시간, 연속 완료(스트릭)를 저장·표시한다.
15. **완료 연출**: 완료 시 축하와 함께 기록(시간·힌트·되돌리기 횟수)을 보여주고 새 게임을 권한다.

### 그 밖
16. **다크 / 라이트 테마** 토글, 선택 저장.
17. **새 게임 / 초기화**: 진행 중 게임을 버릴 때는 한 번 확인을 받는다.

## 기술 제약
- `sudoku/index.html` 단일 파일. CSS·JS 인라인. **외부 라이브러리·폰트·이미지 금지**
  (오프라인 실행과 APK 내장을 위해).
- 이모지·유니코드 글리프 금지. 아이콘은 인라인 SVG (`visual-design-direction`).
- 상태 변경은 DOM 을 유지한 채 클래스만 바꾸는 증분 갱신으로 한다.
- 안드로이드 태블릿과 휴대폰 세로/가로 모두에서 쓸 수 있어야 한다.
- `prefers-reduced-motion` 존중.
- 퍼즐 생성이 UI 를 멈추지 않아야 한다 (전문가 난이도 생성은 오래 걸릴 수 있다).

## 디자인 방향
N-Queens 의 클래식 우드와 형제로 보이게 한다 — **목재 책상 위에 놓인 아이보리 종이
퍼즐**. 격자는 잉크 선, given 은 진한 잉크, 사용자 입력은 다른 색 잉크, 메모는 흐린 연필.
숫자는 세리프. 보드(종이·잉크)는 테마와 무관하게 일정하게 두고 주변 UI 색만 바꾼다.

## 완료 기준 (Acceptance Criteria)
- [ ] 난이도 4단계 각각에서 유일해를 가진 퍼즐이 생성된다.
- [ ] 숫자 입력·메모·지우개·되돌리기/다시하기가 모두 동작한다.
- [ ] 규칙 위반이 즉시 표시된다.
- [ ] 힌트가 정답을 채운다.
- [ ] 앱을 껐다 켜도 진행 중이던 게임이 복원된다.
- [ ] 완료하면 축하 연출과 기록이 뜨고 통계에 반영된다.
- [ ] 다크/라이트 모두에서 읽기 어려운 곳이 없다.
- [ ] 휴대폰 세로 화면에서 가로 스크롤이 생기지 않는다.

## 진행 방식
1. 위 요구사항을 충족하는 버전을 구현하고, 로직은 Node 스텁 테스트로, 화면은 헤드리스
   Chrome 스크린샷으로 검증한다 (`wsl2-browser-testing`).
2. 사용자가 실기기에서 확인하고 알려주는 문제를 반복 수정한다.
3. 만족스러우면 릴리스 서명 AAB 와 스토어 등록 자료를 만든다.
