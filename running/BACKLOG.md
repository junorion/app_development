# 러닝앱 — 백로그

지침: [`docs/러닝앱_Flutter_구현_지침.md`](docs/러닝앱_Flutter_구현_지침.md) (2026-09-20 받음, 이하 "지침")

**위에서부터 하나씩** 진행하고, 끝나면 상태를 고치고 커밋 해시를 적는다.
상태: `대기` · `진행중` · `완료` · `보류` · `확인필요`

지침 12.1 의 순서(M0 → M10)를 따르되, 이 개발 환경에서 **지금 검증할 수 있는 것**과
**실기기·계정이 있어야 하는 것**을 갈라 앞쪽을 먼저 한다.

## 이 환경의 제약 — 지침에 없던 것

| 제약 | 영향 | 대응 |
|---|---|---|
| **macOS 가 없다** (WSL2) | iOS 빌드·서명·TestFlight 불가 | Android 를 먼저 끝낸다. 코드는 처음부터 iOS 설정(Info.plist 문구, Background Modes)을 함께 넣어 두고, 빌드는 클라우드 macOS CI 로 미룬다 (C-3) |
| **에뮬레이터를 못 쓴다** (`/dev/kvm` 권한) | 위젯·화면을 기기 없이 눈으로 확인할 수단이 적다 | 로직은 `flutter test` 단위 테스트로, 화면은 골든 이미지(`matchesGoldenFile`)로 확인한다. 동작은 APK 사이드로드 |
| **테스트 기기는 태블릿**, 진동 모터 없음 | 태블릿은 GPS·걸음 센서가 없는 경우가 많다 — 야외 러닝 검증(M0, 11.3)을 할 수 없을 수 있다 | C-1 로 확인. 걸음 센서가 없는 기기의 `--` 표시(5.4)는 오히려 이 태블릿에서 검증된다 |
| 에이전트는 달릴 수 없다 | 모든 야외 시나리오는 사용자 몫 | 기록을 검증할 수 있게 앱 안에 **진단 화면**(샘플 간격, 버린 샘플 수, 메트로놈 지터)을 둔다 |

## 확인필요 — 답이 올 때까지 기본안으로 진행

| # | 질문 | 기본안 (지금 이대로 진행) |
|---|---|---|
| C-1 | **야외 테스트에 쓸 폰이 있는가** (GPS·걸음 센서가 있는 안드로이드 폰, 가능하면 삼성) | M0 프로브 APK 를 만들어 두고 기기가 정해지면 보낸다 |
| C-2 | **지도 공급자** — Google Maps 는 Google Cloud 결제 계정과 API 키가 필요하다 | 키가 올 때까지 **지도 없이 경로선만** 그린다 (지침 11.1 의 오프라인 대체 화면을 먼저 만드는 셈). 경로 그리기는 지도 공급자와 무관한 좌표 → 화면 투영으로 짠다 |
| C-3 | **iOS 출시 시점** — Apple Developer 계정(연회비)과 클라우드 macOS 빌드가 필요 | Android 출시 후로 미룬다 |
| C-4 | **앱 이름과 패키지명** — 패키지명은 Play 에 올리면 못 바꾼다 | 작업명 "러닝", 패키지 `com.junorion.running`. 첫 Play 업로드 전에 확정 |
| C-5 | 지침 12.2 의 열 가지 | 지침의 기본안 그대로 (페이스 표기, 구간별 색, Ready 요약 0, 해외 포함, A안, 한국어·영어, 마일 지원, 수익화 없음) |
